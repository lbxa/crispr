# @crispr/human-model

A React component and Three.js runtime for the Crispr Next.js application.
`apps/web` owns the application UI; this library owns rendering, camera controls,
model loading, anatomy highlights, and GPU resources. Blender authoring remains
here, alongside the original male/female assets.

## Use in Next.js

```sh
bun run setup # from the repository root
bun run dev   # Next.js is the UI driver
```

Open [http://localhost:3000](http://localhost:3000). Drag to orbit, scroll to zoom,
and use arrow keys to pan. `apps/web/app/model-workspace.tsx` demonstrates the
public API with a lazy client import; no Vite server or iframe is involved.

```tsx
"use client";
import dynamic from "next/dynamic";
const HumanModel = dynamic(
  () => import("@crispr/human-model").then((module) => module.HumanModel),
  { ssr: false },
);

// modelUrl is a consumer-owned URL from the generated asset manifest.
export function AnatomyPreview({ modelUrl }: { modelUrl: string }) {
  return (
    <HumanModel
      modelUrl={modelUrl}
      profile="male"
      highlights={[{ regionId: "liver", color: "#00bfa6" }]}
      onStateChange={(state) => console.debug("anatomy_state", state)}
    />
  );
}
```

Props: required `modelUrl`, optional `profile`, immutable `highlights`
(`regionId`, `color`, `strength`), `className`, and `onStateChange`. State is
`loading → ready | error`; a changed profile or retry starts another load.
The host must provide a nonzero sized container. Profile selection, region
selection, and application workflows are controlled by the consuming UI.
Viewer controls inherit the host's `--foreground`, `--muted`, `--surface`,
`--surface-hover`, `--border`, and `--accent` CSS tokens, with light fallbacks.

## Code map

| File                              | Owns                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------ |
| `src/human-model.tsx`             | React lifetime and loading/error/retry UI                                            |
| `src/scene.ts`                    | Renderer, controls, resizing, visibility, load races, disposal                       |
| `src/model.ts`                    | GLB fetch/cancellation, Meshopt decoding, anchors, geometry/material/texture cleanup |
| `src/highlight.ts`                | Anatomy shader and highlight materials                                               |
| `src/anatomy.ts`                  | Region IDs, display labels, existing result mappings                                 |
| `src/profiles.ts`, `src/types.ts` | Lightweight public metadata/contracts                                                |
| `scripts/build-assets.ts`         | Optimized and content-hashed runtime derivatives                                     |
| `public/models/segmented`         | Canonical Blender-authored GLBs                                                      |

Use package imports; Next.js consumers must not deep-import source files.
The `/profiles` and `/anatomy` entrypoints do not import Three.js, keeping shell
controls small. `/asset-manifest` is generated by the library build and names the
static assets the app publishes.

## Performance and lifecycle

The build welds and simplifies untextured geometry with a bounded error, then
uses Meshopt compression. It preserves body/eye nodes, semantic extras, and all
27 proxy nodes. It never overwrites the original GLBs or Blender sources. Runtime
derivatives are about 650 KB per profile; source exports are 39 MB and 98 MB.
Tests enforce a 3 MB budget and semantic preservation. Smooth normals are
recomputed on the simplified indexed geometry when it loads.

Scenes render on demand while idle, pause offscreen/in hidden tabs, cap pixel
ratio at 2, and suppress highlight animation for reduced motion. Replacement and
unmount abort fetches; generation checks dispose any stale decoded result.
Cleanup disconnects observers/listeners, cancels frames, restores/disposes
highlight materials, disposes models and the renderer, and releases the WebGL
context. Context loss and startup failures offer an explicit retry.

`test/scene.test.ts` proves lifecycle behavior without a GPU. The repository
browser gate checks real WebGL rendering and profile/region interaction.

## Blender MCP

The scoped `.codex/config.toml` runs pinned `blender-mcp==1.6.4` through `uvx`, so copied checkout paths and virtual environments are not required. Its add-on source is `.mcp/blender-mcp/addon.py`. Telemetry is disabled. Restart Codex after changing MCP configuration. The optional virtual environment below is only needed for manual bridge tooling. Workspace dependencies use the monorepo's root `bun.lock`.

To recreate the optional bridge environment, run from `libs/human-model`:

```sh
uv venv .mcp/blender-mcp/.venv
uv pip install --python .mcp/blender-mcp/.venv/bin/python -r .mcp/blender-mcp/requirements.txt
```

The exported models live in `public/models/`. Regenerate either profile through the project-local Blender MCP when its source collection changes:

```sh
bun run --cwd libs/human-model export:model male
bun run --cwd libs/human-model export:model female
```

## Anatomy regions

The component loads optimized derivatives of the Blender-authored assets in
`public/models/segmented/`. The source assets contain 15 shared anatomy regions as
27 soft ellipsoid proxy nodes with semantic extras. The proxies are removed
from rendering after their transforms are read. Posterior regions such as the
kidneys and spine are rendered as subsurface projections through the opaque
body, keeping them visible from the default front view.

With the canonical `.blend` open and Blender MCP connected:

```sh
bun run --cwd libs/human-model inspect:blender   # inspect source collections
bun run --cwd libs/human-model segment:model     # export both segmented GLBs
bun run --cwd libs/human-model verify:segments   # validate the semantic contract
```

Region cues are surface associations for product visualization, not diagnostic
anatomy. See `docs/blender-segmentation.md` for the export contract.

## Changelog

### 2026-10-17

- The viewer omits a camera reset button to keep the workspace minimal. Scene reframing on model loads and viewport changes remains internal to the renderer.
- Type checks depend on this workspace's asset build because the runtime asset tests import the generated manifest. Warm local output can hide this dependency; preserve the task ordering for clean CI checkouts.
- Track this workspace and its canonical assets as ordinary files in the monorepo. An inherited Git submodule pointer without `.gitmodules` prevented clean CI clones; do not reintroduce a nested repository when copying authoring assets or tooling.
- Viewer feedback inherits host color tokens so the reusable scene fits the app's minimal workspace without adding a separate themed panel.
- `HumanModel` is a controlled React library component used by `apps/web`; Next.js owns the main UI so growing product features do not become coupled to page-global Three.js code.
- Kept existing anatomy shaders and Blender semantics behind `src/scene.ts` lifecycle ownership, with cancellation and stale-result disposal to make profile changes, retries, and React Strict Mode safe.
- Renderer allocation waits for the first animation frame and cancels during Strict Mode's effect replay; retry creates a fresh canvas. This avoids reusing a context that cleanup intentionally lost.
- Added optimized, hashed runtime derivatives and a build manifest rather than serving full authoring exports. This preserves source fidelity while keeping network payloads and GPU geometry appropriate for an interactive web app.
